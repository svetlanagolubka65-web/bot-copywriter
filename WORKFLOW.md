# Алгоритм работы над сайтом «НейроСвета»

Этот файл фиксирует наш порядок работы, чтобы не потерять договорённости и не переделывать уже принятое.

## Главное правило

**Ничего не ломать.**

- Не удалять существующие разделы без прямого разрешения Светланы.
- Не менять общий стиль сайта без согласования.
- Перед крупным изменением сохранять текущую рабочую версию.
- Все изменения делать поэтапно и с возможностью отката.

## Стиль сайта

- Тёплая светлая палитра: кремовый, бежевый, золотистый.
- Мягкие тени, округлые карточки, лёгкое свечение.
- Заголовки: Playfair Display.
- Основной текст: Raleway.
- ИИ должен выглядеть дружелюбным и понятным, а не холодным и техническим.
- В центре бренда — Светлана и экосистема «НейроСвета».

## Порядок работы

### 1. Проверить текущее состояние

- Открыть `index.html` и `preview.html`.
- Проверить, что сайт работает.
- Убедиться, что прежние блоки не исчезли.

### 2. Сделать изменение

- Вносить только согласованную задачу.
- Не переписывать весь сайт, если требуется изменить один блок.
- Использовать существующие цвета, шрифты и стили.

### 3. Проверить адаптивность

Проверять минимум на ширинах:

- 1440 px — большой экран
- 1024 px — ноутбук
- 768 px — планшет
- 390 px — телефон
- 320 px — маленький телефон

На широком экране карточки могут быть 3×2 или 6 в ряд, если текст остаётся читаемым.
На планшете — 2–3 карточки в ряд.
На телефоне — 1 карточка в ряд.

### 4. Проверить содержимое

- Заголовки не обрезаны.
- Кнопки читаемы и нажимаются.
- Аватары не растянуты.
- Статусы соответствуют реальности.
- Telegram-ссылки ведут на нужных ботов.
- Нет орфографических ошибок.

### 5. Сохранить работу

- Сделать осмысленный commit.
- Запушить изменения в `main`, если задача уже одобрена Светланой.
- В сообщении commit кратко описать, что изменено.

Пример:

`Add responsive AI assistants section with mystery card`

### 6. Проверить публикацию

После push открыть:

- `https://svetlanagolubka65-web.github.io/bot-copywriter/`
- `https://svetlanagolubka65-web.github.io/bot-copywriter/preview.html`

GitHub Pages может обновляться несколько минут.

## Что нельзя делать

- Не удалять фото, отзывы, портфолио, цены и контакты.
- Не заменять весь `index.html` новым макетом без отдельного решения.
- Не использовать случайные новые цвета.
- Не вставлять выдуманные ссылки.
- Не публиковать неработающие кнопки как рабочие.
- Не хранить токены, пароли и ключи API в GitHub.

## Следующие задачи

1. Заменить временные изображения в `preview.html` на настоящие файлы аватаров.
2. Добавить качественный аватар Джарвиса — бело-золотой робот-человечек с указкой.
3. Сохранить загадочный силуэт для будущего помощника.
4. Проверить реальные ссылки всех Telegram-ботов.
5. Перенести готовый блок из `preview.html` в `index.html`, не меняя остальные части сайта.
6. Проверить сайт на телефоне, планшете и ноутбуке.
7. После проверки запушить и убедиться, что GitHub Pages обновился.

## Отчёт после каждой задачи

После выполнения сообщить Светлане простыми словами:

- что было сделано;
- какие файлы изменены;
- что осталось прежним;
- ссылка на результат;
- commit SHA.
